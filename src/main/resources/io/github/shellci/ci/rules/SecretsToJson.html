Why is this an issue?

toJSON(secrets) serializes every secret available to the job into a single value. Any step, action or tool that receives it (and anything it logs, uploads or forwards) gets all of them, not only the one it needs. GitHub only masks secrets in logs when they appear verbatim; a JSON blob that is re-encoded, split or transformed may be logged in clear.

How to fix it

Reference the individual secrets the step needs.

Noncompliant code example

- run: ./deploy.sh
  env:
    ALL_SECRETS: ${{ toJSON(secrets) }}  # Noncompliant

Compliant solution

- run: ./deploy.sh
  env:
    DEPLOY_KEY: ${{ secrets.DEPLOY_KEY }}
