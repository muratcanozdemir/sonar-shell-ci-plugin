Why is this an issue?

Pipeline files are committed to the repository. A password, token or key written into an env: or variables: block is readable by everyone with read access to the repository, its forks and clones, stays in git history after it is removed, and is not masked in job logs.

This rule reports literal values assigned to variables whose name suggests a secret (PASSWORD, API_KEY, DEPLOY_TOKEN, ...). Values that reference a secret, variable or expression are not reported.

How to fix it

Revoke the exposed credential, store a new one in the CI system's secret store and reference it.

Noncompliant code example

# GitLab CI
variables:
  DEPLOY_TOKEN: "glpat-8s7dF6g5H4j3K2l1"  # Noncompliant

# GitHub Actions
env:
  NPM_TOKEN: npm_a8D7f6G5h4J3k2L1  # Noncompliant

# Azure Pipelines
variables:
  - name: SONAR_TOKEN
    value: sqa_1234567890abcdef  # Noncompliant

Compliant solution

# GitLab CI: define DEPLOY_TOKEN as a masked, protected CI/CD variable in the project settings
deploy:
  script: ./deploy.sh --token "$DEPLOY_TOKEN"

# GitHub Actions
env:
  NPM_TOKEN: ${{ secrets.NPM_TOKEN }}

# Azure Pipelines: use a secret variable or a variable group linked to Key Vault
variables:
  - group: deploy-secrets
