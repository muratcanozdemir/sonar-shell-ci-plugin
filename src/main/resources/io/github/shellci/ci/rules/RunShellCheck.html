Why is this an issue?

Pipeline steps (GitHub Actions run:, GitLab CI script:/before_script:/after_script:, Azure Pipelines script:/bash:/Bash@3/CmdLine@2/AzureCLI@2) are shell scripts and fail in the same ways as any other script: unquoted variables split and glob, cd failures go unnoticed, pipelines hide errors. Because they run in CI, these bugs usually surface as flaky or silently wrong builds and releases.

This rule runs ShellCheck on every script executed by bash or sh and reports its findings at the corresponding place in the pipeline file. Template expressions (${{ }}, $[ ], Azure $(macros), GitLab $[[ inputs ]]) are treated as plain words. GitLab jobs whose image is Alpine or BusyBox are checked as POSIX sh, others as bash; a job's before_script and script are checked together as one session. ShellCheck must be installed where the analysis runs.

The minimumLevel parameter selects the lowest ShellCheck level reported, and excludedCodes lists checks to ignore. Each finding's message starts with its ShellCheck code; see the ShellCheck wiki page for that code for details.

How to fix it

Fix the script as explained by the ShellCheck finding, or add # shellcheck disable=SCxxxx inside the script before the offending line.

Noncompliant code example

- run: |
    cd $BUILD_DIR      # SC2164: Use 'cd ... || exit' in case cd fails
    rm -rf $OUT/*      # SC2115: Use "${var:?}" to ensure this never expands to /*

Compliant solution

- run: |
    cd "$BUILD_DIR" || exit 1
    rm -rf "${OUT:?}"/*
