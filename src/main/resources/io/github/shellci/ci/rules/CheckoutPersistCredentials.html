By default actions/checkout writes the GITHUB_TOKEN into the checked-out repository's .git/config so later steps can push. Every later step, action and dependency can read it there, and workflows that upload the workspace as an artifact publish it ("ArtiPACKED").

Azure Pipelines does the same for System.AccessToken when a checkout step sets persistCredentials: true.

Ask Yourself Whether

  • Later steps do not need to run authenticated git commands.
  • The workflow uploads the workspace or runs third-party code after the checkout.

There is a risk if you answered yes to any of those questions.

Recommended Secure Coding Practices

Set persist-credentials: false (GitHub Actions) or leave persistCredentials unset (Azure Pipelines), and pass a token explicitly to the steps that need to push.

Sensitive Code Example

# GitHub Actions
- uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683  # Sensitive

# Azure Pipelines
- checkout: self
  persistCredentials: true  # Sensitive

Compliant Solution

# GitHub Actions
- uses: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683
  with:
    persist-credentials: false

# Azure Pipelines
- checkout: self
- bash: git push origin HEAD:release
  env:
    SYSTEM_ACCESSTOKEN: $(System.AccessToken)
