Job, service and step containers (GitHub Actions uses: docker://...) referenced without a tag, or with latest, change whenever the image is republished. The pipeline then runs code nobody reviewed, builds are not reproducible, and a compromised or typo-squatted image reaches every job at once. Version tags are also mutable; only a digest (@sha256:...) guarantees the exact image.

Ask Yourself Whether

  • The image comes from a public registry or a publisher you do not control.
  • The job has access to secrets, deploy credentials or publishes artifacts.

There is a risk if you answered yes to any of those questions.

Recommended Secure Coding Practices

  • Pin images to a digest and let Dependabot or Renovate update it. Keep the tag for readability: node:22.11@sha256:....
  • At least pin an explicit version tag, never rely on latest.

By default the rule reports untagged and latest images only. Set the requireDigest parameter to also report version tags.

Sensitive Code Example

# GitLab CI
image: python          # Sensitive
services:
  - postgres:latest    # Sensitive

Compliant Solution

image: python:3.13@sha256:8f0ad0e2b7d7d5c6ef3f1c5c7e2b0ab6a0d3c1f9e4b8a7c6d5e4f3a2b1c0d9e8
services:
  - postgres:17.2
