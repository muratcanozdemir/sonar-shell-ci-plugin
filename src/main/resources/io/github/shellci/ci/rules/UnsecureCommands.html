Why is this an issue?

The set-env and add-path workflow commands were disabled in 2020 because any process that can print to the job log, for example a test printing an issue title or a dependency's install script, could use them to set LD_PRELOAD, NODE_OPTIONS or PATH for later steps and take over the job. Setting ACTIONS_ALLOW_UNSECURE_COMMANDS: true turns them back on.

How to fix it

Remove the variable and write to the $GITHUB_ENV and $GITHUB_PATH files instead.

Noncompliant code example

env:
  ACTIONS_ALLOW_UNSECURE_COMMANDS: true  # Noncompliant
steps:
  - run: echo "::set-env name=TOOL_HOME::/opt/tool"

Compliant solution

steps:
  - run: echo "TOOL_HOME=/opt/tool" >> "$GITHUB_ENV"
