Piping a downloaded script straight into a shell (curl ... | bash, bash <(curl ...), PowerShell iwr ... | iex) runs whatever the server returns at that moment, with the job's credentials. A compromised host, DNS, CDN or release page, or a truncated download, executes in your pipeline without any check.

Ask Yourself Whether

  • The URL is outside your control, or not pinned to a fixed version.
  • The job has access to secrets, deploy credentials or publishes artifacts.

There is a risk if you answered yes to any of those questions.

Recommended Secure Coding Practices

  • Prefer a package manager, a pinned container image or a pinned action that provides the tool.
  • Otherwise download a fixed version to a file, verify its checksum or signature, then run it.

Sensitive Code Example

script:
  - curl -fsSL https://get.example.com/install.sh | bash  # Sensitive

Compliant Solution

script:
  - curl -fsSLo install.sh https://get.example.com/v1.4.2/install.sh
  - echo "3f5e7a...c2d1  install.sh" | sha256sum -c -
  - bash install.sh
